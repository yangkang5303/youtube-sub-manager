## 数据存储与缓存

### 订阅快照

应用把订阅快照写入本地 SQLite，之后的页面加载直接读本地库（约 0 秒），
只在满足以下任一条件时才重新调用 YouTube API：

- 本地没有任何数据（首次运行）
- 距上次更新超过 `REFRESH_INTERVAL_SECONDS`（默认 6 小时）
- 页面点「🔄 刷新数据」或请求带 `?refresh=1`

这样能大幅减少 API 调用量，避免触发每日配额限制。

### 头像（缩略图）缓存

浏览器如果直接引用 `yt3.ggpht.com` 的图片，一次渲染几百个频道会并发几百个请求，
Google 图片 CDN 会返回 **429 Too Many Requests**。

因此前端统一改用本地代理 `/thumb/<channel_id>`：

- 首次访问时后端下载一次，存到 `cache/thumbs/<channel_id>.jpg`（约 5KB/张）
- 之后所有请求都从本地磁盘返回，并带 30 天 `Cache-Control`
- 每次刷新数据后在后台线程预热全部头像（并发上限 4，避免自己触发限流）
- 下载失败时返回占位图且不缓存，下次访问会自动重试

结果：页面加载 **0 个 CDN 请求**，切换标签页也只读浏览器本地缓存。

### 分类（标签）是怎么来的

分类来自 YouTube Data API 的 `channels.list(part="topicDetails")`，
字段 `topicDetails.topicCategories` 是一组 Wikipedia 主题 URL，再映射成中文
（映射表在 `app.py` 的 `CATEGORY_MAP`）：

```
https://en.wikipedia.org/wiki/TechArticle   -> 科技
https://en.wikipedia.org/wiki/Pop_music     -> 音乐
https://en.wikipedia.org/wiki/Vehicle       -> 汽车
```

**一个频道通常有 2–3 个标签（最多 7 个）**，本应用全部保留：

- 每个频道在列表里显示它的**所有**标签，第一个为主分类（高亮）
- 筛选某个分类时，只要频道的**任一**标签命中就会出现
- 「分类整理」里一个频道会出现在它所属的每一个分类下
- 因此分类视图的「归类次数」会大于频道总数（例：270 个频道 → 565 次归类）

点击列表里的任意标签即可直接按该分类筛选。

## 刷新机制与 API 配额

### 什么时候会调 YouTube API

**按需刷新**（默认）：不打开页面就完全不消耗配额。

```
打开页面 → 本地快照是否超过 REFRESH_INTERVAL_SECONDS（默认 6 小时）？
   ├─ 否 → 直接读本地 SQLite（毫秒级，0 配额）
   └─ 是 → 拉一次全量数据 → 落库 → 返回
```

也可以随时点右上角 **🔄 刷新数据** 手动强制拉取。

想让它在你没打开页面时也保持最新，设 `AUTO_REFRESH_SECONDS`（如 `7200` = 每 2 小时）。

### 用的是哪些 API

| API | 单次消耗 | 用途 |
| --- | --- | --- |
| `subscriptions.list` | 1 单位 | 拉订阅列表（50 个/批） |
| `channels.list` | 1 单位 | 拉频道详情与分类（50 个/批） |
| `activities.list` | **1 单位** | 每个频道最近一次上传时间 |
| ~~`search.list`~~ | ~~100 单位~~ | **已不使用** |

> 早期版本用 `search.list` 查最新上传（100 单位/次 × 每个频道），
> 几百个频道就会瞬间耗尽配额。现已改为 `activities.list`，**便宜 100 倍**。

### 会触发「Search Queries 每日 100 次」限额吗

**不会。** 那是 `search.list` 专属的独立限额，本应用**完全不调用** `search.list`，
所以该项用量恒为 **0 / 100**。

### 实际消耗（以 256 个订阅为例）

```
subscriptions.list    6 次 × 1 单位 =   6
channels.list         6 次 × 1 单位 =   6
activities.list     256 次 × 1 单位 = 256
────────────────────────────────────────
一次全量刷新         268 次请求   = 268 单位   （占每日 10000 的 2.7%）
```

| 刷新周期 | 每天次数 | 消耗单位 | 占日配额 |
| --- | --- | --- | --- |
| 1 小时 | 24 | 6,432 | 64% |
| 2 小时 | 12 | 3,216 | 32% |
| 3 小时 | 8 | 2,144 | 21% |
| **6 小时（默认）** | 4 | 1,072 | **11%** |
| 12 小时 | 2 | 536 | 5% |
| 24 小时 | 1 | 268 | 3% |

即使调到 1 小时也仍在配额内，默认的 6 小时则非常宽裕。

> 配额是按**每个 Google Cloud 项目**算的。这也是为什么 [google-oauth.md](google-oauth.md)
> 强调每人要申请自己的凭证 —— 共用项目会共用同一份配额。

### 「X 天前」为什么是准的

`days_since_upload` **不沿用入库时的快照值**，而是在每次读取本地库时
按当前时间重新计算（`load_subscriptions()` 里做的）。
所以即使数据是 5 小时前拉的，显示的「今天 / 昨天 / 3天前」也是按现在算的，
且这个过程**不消耗任何 API 配额**。

## 自定义标签

除了 YouTube 自动分类，还可以给频道打自己的标签。

### 怎么用

1. 点筛选栏右侧的 **☑ 批量打标签**（按钮变紫表示已进入）
2. **点击频道卡片**即可选中/取消（整张卡片都是开关，不会有误触跳转）
3. 配合 **全选 / 反选 / 清空** 快速圈定范围
   - 「全选」只作用于**当前筛选结果**（搜索、分类筛选都算）
4. 在输入框里**输入新标签名**，或从下拉里**选一个已有的**
5. 点 **＋ 添加标签**（或直接回车）；也可以 **－ 移除标签**
6. 点 **退出** 结束（会清空选择）

### 单个移除（不用进批量模式）

把鼠标移到频道卡片上**自定义标签的右上角**，会出现一个小 **×**，点一下就把这个标签
从该频道移除 —— 相当于把这个频道移出该标签分组。误点也没关系，底部提示里可以**撤销**。

> 只有「我的标签」（紫色 ✎）有 ×；YouTube 自动分类（蓝色）来自 API，不能在这里删。
> 触屏设备没有 hover，× 会常驻显示。

### 几个细节

- 操作栏**吸顶**，滚动列表时始终可见
- 新标签**立即出现在分类筛选区**（带 ✎ 前缀和紫色调，与自动分类区分）
- 卡片上的自定义标签同样是紫色 ✎ 样式，一眼能区分
- 点自定义标签可以直接筛选
- 标签只存在本地数据库，**不消耗 YouTube API 配额**，也不影响你在 YouTube 的订阅

### 限制

- 单个标签名最长 24 字符，每个频道最多 20 个标签
- 重复添加是幂等的（不会重复，返回 `changed: 0`）

### 多环境同步

**标签不会自动同步。** 它保存在各自环境的 SQLite 里（不是 YouTube 侧）：

| 环境 | 标签存放位置 |
| --- | --- |
| 本地运行 | `./data.db` |
| Docker 部署 | 容器内 `/app/data/data.db`（挂载到宿主机 `./data/`） |

日常使用不用管 —— 直接在你在用的那个环境的网页上打标签即可。
但如果你**同时**在本机和服务器上用，两边的标签是独立的，需要时用同步脚本对齐
（标签以 `channel_id` 为键，两边订阅同一账号时可直接对应）：

```bash
# 本机 → 服务器（把本机标签推上去）
python3 scripts/sync_labels.py --to http://<服务器地址>:8765

# 服务器 → 本机（把线上标签拉下来）
python3 scripts/sync_labels.py --from http://<服务器地址>:8765 --to http://localhost:8765

# 只看差异，不做改动
python3 scripts/sync_labels.py --to http://<服务器地址>:8765 --dry-run

# 目标开了访问口令
python3 scripts/sync_labels.py --to http://... --user admin --password 你的密码
```

脚本是**双向增量**的：只补缺失的、只删多余的，两边一致时直接提示无需同步。
运行 `python3 scripts/sync_labels.py --help` 看全部参数。

## 界面细节

### 频道卡片列数

宽屏下频道自动排成多列卡片，**列数由容器宽度决定，最多 6 列**：

| 浏览器窗口 | 列数 | 卡片宽度 |
| --- | --- | --- |
| ≤ 560px | 1（横向行：头像 + 信息 + 按钮） | 整行 |
| 561 ~ 699px | 2 | 约 260px |
| 700 ~ 899px | 3 | 约 216px |
| 900 ~ 1099px | 4 | 约 210px |
| 1100 ~ 1299px | 5 | 约 206px |
| **≥ 1300px** | **6（上限）** | 约 203 ~ 226px |

实现方式：容器用 `repeat(auto-fill, minmax(200px, 1fr))` 自适应列数，
大屏逐级放宽容器上限到 **1440px** —— 7 列需要 1460px，所以永远不会超过 6 列。

≥561px 时卡片切换为**竖向布局**（头像在上、频道名居中可折两行、标签、退订按钮撑满底部）。

### 卡片版式（固定高度）

每张频道卡片都是**4 个固定行高区域**，所以同一行的卡片高度完全一致：

```
┌──────────────────────────────┐
│      ┌────┐  频道名称（最多2行）│  ← 48px 头像+名字作为一组水平居中
│      │头像│  超出 2 行自动省略… │         名字垂直居中对齐头像圆心
│      └────┘                  │
│        👤 1.2M  🎬 890        │  ← 20px 订阅/视频数，居中
│  [音乐] [生活方式] [✎我的收藏]  │  ← 47px 标签，最多 2 行，超出裁掉
│  [美食]                       │
│  ● 活跃 · 3天前         [退订] │  ← 32px 活跃靠左、退订靠右
└──────────────────────────────┘
   总高 189px（所有卡片一致）
```

| 区域 | 行高 | 说明 |
| --- | --- | --- |
| 头像 + 名字 | 48px | 两者作为一组**水平居中**；名字**垂直居中**，所以 1 行时该行中心、2 行时第 1-2 行交界，都正好与头像圆心齐平。名字 `-webkit-line-clamp: 2`，超 2 行省略 |
| 订阅 / 视频数 | 20px | 居中显示 |
| 标签 | 47px | 2 行（19px × 2 + 4px 间距），第 3 行起裁掉 |
| 活跃 + 退订 | 32px | 活跃情况靠左，退订按钮靠右 |

窄屏（≤560px）各区域整体压缩一档，总高 **165px**。

行高通过 CSS 变量定义，想微调改这几行即可：

```css
.sub-row {
    --card-head:   48px;
    --card-status: 20px;
    --card-tags:   47px;
    --card-foot:   32px;
}
```

> 标签区顶部有 5px 内边距（用负 margin 抵消视觉偏移），
> 是给标签右上角浮出的移除「×」留空间，否则会被 `overflow: hidden` 裁掉。

### 主题与配色

右上角 🌙 / ☀️ 按钮切换深浅色：

- 首次访问**跟随系统**（`prefers-color-scheme`），手动切换后会记住选择
- 系统主题变化时，未手动选择过的会自动跟随
- 页面 `<head>` 有内联脚本，在 CSS 生效前就设好主题，**刷新不会闪屏**
- 全部颜色通过 CSS 变量定义（`:root` 深色 / `[data-theme="light"]` 浅色），便于统一调整

配色刻意**降低饱和度**，不使用纯红/纯绿等刺眼原色：

| 角色 | 旧值（饱和度） | 深色（饱和度） | 浅色（饱和度） |
| --- | --- | --- | --- |
| 强调 accent | `#ff0000` (100%) | `#c07a72` (38%) | `#a8625a` (31%) |
| 危险 danger | `#e74c3c` (78%) | `#b6746b` (34%) | `#a25a52` (33%) |
| 成功 success | `#2ea640` (57%) | `#7ba585` (19%) | `#4b7859` (23%) |
| 信息 info | `#3498db` (70%) | `#7b9ab0` (25%) | `#54748f` (26%) |

正文与语义色在两种模式下均满足 WCAG AA 对比度（≥4.5:1）。

## HTTP API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 主页面（未授权时 302 到 `/authorize`） |
| GET | `/authorize` | 授权页（显示 Google 授权链接） |
| GET | `/authorize/status` | 授权进度轮询：`{done, pending, error}` |
| GET | `/healthz` | 健康检查 + 版本自检（**不需要授权**） |
| GET | `/api/subscriptions` | 订阅列表（优先本地库，支持 `?refresh=1`） |
| GET | `/api/summary` | 汇总统计 + 分类分组 |
| POST | `/api/refresh` | 强制重新从 YouTube 拉取并落库 |
| POST | `/api/unsubscribe/<subscription_id>` | 退订频道（同时更新本地库） |
| POST | `/api/labels` | `{"channel_ids": [...], "label": "名称", "action": "add"\|"remove"}` |
| GET | `/thumb/<channel_id>` | 本地头像缓存代理 |
